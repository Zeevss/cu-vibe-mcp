# SSO ЦУ без браузера

Исследование публичных страниц выполнено 16.11.2026. Учётные данные не отправлялись. Реальным HTTP-клиентом подтверждено получение шага `emailLogin`; остальные ветки восстановлены из публичного JavaScript темы и проверяются синтетическими ответами. Полный вход, реальные MFA/блокировки и приём callback сервером LMS пока требуют проверки пользователем.

## Наблюдавшийся протокол

- Портал `/auth` — Angular SPA, `/api/auth` не является endpoint входа.
- `/dynamical-config/configuration.json` публикует `authUrl`: `https://id.centraluniversity.ru/realms/central-university/protocol/openid-connect`.
- Публичный модуль портала `chunk-Z3MSVWNH.js` строит GET `authUrl + /auth`: `response_type=code`, `client_id=api-gateway`, `scope=openid email offline_access`, `redirect_uri=https://my.centraluniversity.ru/api/account/signin/callback`.
- HTML IdP содержит `window.authConfiguration`, а формы рисует тема `cu_theme`, на момент исследования `ru/main.js?v=58`. `currentState.activePage` определяет шаг, `urls.loginAction` — адрес POST. Названия/hash ресурсов не используются runtime и могут меняться.
- Тема создаёт обычный HTML form POST. Программа воспроизводит поля, сохраняет временные cookies внутри одного HTTP-клиента и использует только action, выданный текущим ответом.

| Шаг темы | Поля POST |
|---|---|
| `emailLogin` | `username` |
| `password` | `password` |
| `passwordLogin` | `username`, `password`, `credentialId` |
| `otpEmail`, подтверждение | `otp`, `submit=submit` |
| `otpEmail`, повторная отправка | пустой `otp`, `resend=resend` |
| `otp`, подтверждение SMS | `phoneNumber`, `code`, `action=verify`, `credentialId` |
| `otp`, повторная отправка | `phoneNumber`, `action=sendCode` |

Телефон и credentialId берутся из ответа IdP, не запрашиваются моделью. Если телефон отсутствует, отправки нет. Повторная отправка требует явного `/resend`. Регистрация, смена/сброс пароля, подтверждение почты по ссылке и настройка MFA не автоматизированы: CLI объясняет действие на сайте и завершает попытку. CAPTCHA не обходится.

## Проверка и хранение

Runtime добавляет случайный OIDC `state` и проверяет его перед переходом на callback LMS. Поддержка этого callback в реальном аккаунте пока не подтверждена. Redirect ограничен HTTPS и двумя точными хостами IdP/LMS; POST 307/308 не пересылается повторно. Action принимается только для `/realms/central-university/login-actions/authenticate`. Чужой origin, неизвестная форма или неизвестный шаг останавливают вход.

Сырые HTML, сообщения сервера, action URLs, password/OTP не выводятся. Парсер читает только известные литералы конфигурации и не исполняет JavaScript. Ответы ограничены 1 МиБ, цепочка — 12 запросами. Нет автоматических повторов POST при сетевой ошибке: результат отправки может быть неизвестен.

Вход ограничен общим сроком 30–900 секунд, с проверкой после пользовательского ввода, пятью вводами на тип шага и двумя повторными отправками. Ctrl+C закрывает HTTP-клиент, временные cookies очищаются. Межпроцессный lock запрещает второй CLI login в той же папке данных. Это не блокировка операции импорта cookie; не выполняй её одновременно со входом.

После callback программа проверяет cookies через `/api/micro-lms/students/me` и только затем заменяет локальную сессию. Сохраняются cookies LMS, не пароль, не одноразовый код и не отдельный OIDC refresh token. Python не гарантирует немедленное стирание строк из оперативной памяти. Неудачная попытка не заменяет рабочую сессию.

## ChatGPT

`auth_login` возвращает `local_input_required` и команду. Пользователь выполняет её в собственном терминале. `auth_status` видит сохранённую сессию, но не прогресс независимого CLI. Секреты не входят в схемы MCP. Если скрытый ввод недоступен, программа завершается вместо перехода к открытому stdin.

Вход в Note и чтение силлабусов — отдельный механизм. Selenium остаётся для рендеринга Note; авторизация LMS от него больше не зависит.
