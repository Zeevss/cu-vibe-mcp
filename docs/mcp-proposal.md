# Предложение по интеграции MCP

> Исследовательский документ. Текущая реализация и результаты её проверки описаны в [implementation.md](implementation.md).

Это проектная рекомендация по результатам обзора портала, а не реализованный интерфейс. Перед реализацией остаётся техническая проверка автономной авторизации, выгрузки и отдельных типов работ.

## Подход

Основной источник учебных данных — структурированный API LMS, уже используемый порталом. Браузер полезен для первоначального входа и исследования, но выполнение каждого запроса MCP через клики сделает интеграцию хрупкой.

Сначала требуется подтвердить чтение API отдельным клиентом в разрешённой пользовательской сессии. Конкретный способ передачи/обновления сессии пока не выбран. Не следует заранее обещать вход по логину/паролю, бессрочный cookie или доступ к внутренним сервисам через токен LMS.

Два силлабуса прочитаны в браузере. Силлабусы — отдельный источник `note.cu.ru`, а внешние условия и материалы могут вести в Drive и другие сервисы. Наличие ссылки не означает доступность текста. Для каждого внешнего источника нужны отдельная проверка доступа и явный результат: прочитано, требуется вход, недоступно или только ссылка.

## Предлагаемые инструменты первой версии

| Инструмент | Что возвращает |
|---|---|
| `list_courses` | Актуальные/архивные курсы, фильтры участия, пагинация, ссылки на курс и силлабус |
| `get_course` | Метаданные, дерево тем и лонгридов, прогресс и ближайшие сроки |
| `get_gradebook` | Серверные баллы работ, нормированные и дополнительные оценки, средние/веса/вклады активностей, пороги и сработавшие блокеры |
| `get_academic_record` | Электронная зачётка по сессиям с видом контроля и оценкой |
| `list_assignments` | Работы по курсу, состоянию, диапазону дат и архивности; исходный и личный дедлайны |
| `get_assignment` | Полное условие, внешние ссылки, статус, даты, баллы, вложения решения; комментарии и история событий; API комментариев ещё уточнить |
| `get_quiz_result` | Завершённая попытка, вопросы и ответы, результаты, политика попыток и таймер; без запуска новой попытки |
| `get_late_days` | Общий баланс, использованные LD, признаки разрешения переноса и пределы, если их удастся достоверно получить |
| `get_longread` | Упорядоченные блоки, текст, формулы и ссылки на файлы с происхождением |
| `export_material` | Проверенное скачивание выбранного материала и метаданные; извлечение текста там, где поддерживается |
| `get_syllabus` | Текст/таблицы силлабуса, ссылка и время получения либо точная причина недоступности |

Дополнительные инструменты после проверки: расписание, посещаемость, уведомления и доступные записи пар. Запись на пары, выбор курсов, отправка решений, комментарии и расход LD — отдельные операции изменения, вне первой версии чтения.

## Семантика результата

- Всегда возвращать ID, ссылку на исходную страницу, время получения и полноту результата.
- Даты хранить с часовым поясом; для пользователя отображать Europe/Moscow.
- Отдавать исходный статус API вместе с подписью; неизвестные значения не терять.
- `null` оценки сохранять как отсутствие оценки. Не подменять нулём.
- Различать баллы LMS, итог с блокерами, прогресс и оценки зачётки.
- Средний по оценённым работам можно предлагать как отдельную вычисленную метрику с явной формулой, не называя его средним LMS.
- Не путать общий LD-баланс, использованные дни конкретной работы и проверенную возможность нового переноса.
- Отдельно фильтровать незавершённые работы архивных курсов.
- Не считать отсутствие статистики посещаемости нулевой посещаемостью.
- Не считать строку в списке видеособытий доказательством существования записи.
- Не выдавать недоступный внешний файл за прочитанное условие.
- Кэшировать материалы по идентификатору/версии; текущие баллы, статусы и сроки обновлять отдельно.
- Ограничивать объём ответа и поддерживать пагинацию/выбор темы, чтобы не загружать все материалы в каждый ответ.

## Критерии готовности

1. Каталог полностью вычитывает актуальные и архивные курсы с пагинацией.
2. Детальные баллы и итоги совпадают с UI минимум для трёх разных курсов; объясняются блокеры и нормирование.
3. Список дедлайнов использует личные сроки и полные даты; есть отдельный фильтр архивных курсов.
4. На примере известного переноса корректно разделены исходный срок, личный срок, потраченные LD и остаток.
5. Один HTML-материал, один PDF и один файл задания реально скачаны/прочитаны; непрочитанные внешние источники явно помечены.
6. Силлабусы минимум двух курсов прочитаны после получения доступа, либо функция честно возвращает недоступность.
7. Истечение сессии приводит к понятному запросу повторного входа, а не к пустому списку курсов.
8. В артефактах, логах и MCP-ответах нет пароля, сессионных cookies, токенов и лишних персональных полей.

До завершения этих проверок корректная формулировка результата — «подтверждена структура данных и возможность чтения в браузере», а не «полная интеграция работает».
