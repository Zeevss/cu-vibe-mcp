# Исследование учебного портала ЦУ

> Исследовательский документ. Текущая реализация и результаты её проверки описаны в [implementation.md](implementation.md).

Дата наблюдения: 2026-11-15, часовой пояс пользователя — Europe/Moscow.

## Объём и статус

Исследован интерфейс личного аккаунта после ручного входа пользователя. Через браузер наблюдались ответы реальных запросов, вызванных навигацией. Перебора URL, чужих аккаунтов и изменения учебных данных не было. Диалог LD был открыт для чтения и отменён без применения переноса.

Проведён обзор основных разделов портала. Учебное ядро подробно проверено на БД (1127), английском (1364) и архивной ведомости информационной безопасности (880). Прочитаны два силлабуса. Это исследование функций и источников данных, а не проверка каждой работы каждого курса или готового автономного клиента.

В продолжении после входа доступ к порталу и двум силлабусам восстановлен. Устаревшие ограничения доступа из первого черновика больше не действуют. Сохраняются технические пробелы: локальное скачивание/извлечение файлов, внешний Drive, автономная авторизация и режим лучших N работ. Изменения учебных данных не выполнялись.

## Структура курса и материалы

Подтверждённая цепочка идентификаторов:

`course → theme → longread → material / exercise → personal task`

Ответ `overview` содержит темы, их порядок, публикацию и массивы лонгридов. Лонгрид сам по себе не равен домашнему заданию: внутри могут быть текст, файлы и оцениваемые упражнения. Персональная работа имеет отдельный `taskId`, упражнение — `exercise.id`, блок материала — собственный `id`.

На примере недели 8 БД:

- Курс 1127, тема 10010.
- Лонгрид материалов 19567; лонгрид ДЗ 43826; задачи семинара 43829.
- В материалах есть HTML-заголовки и два PDF: лекция и лонгрид.
- `viewContent` представляет собой JSON-строку; в текстовом блоке `value` содержит HTML, несмотря на discriminator `markdown`.
- Для файла доступны имя, относительный `filename`, версия, размер и тип. Лонгрид PDF имеет размер 487640 байт; это метаданные ответа, не результат проверки скачанного файла.
- Нажатие скачивания вызвало успешный ответ `/api/micro-lms/content/download-link`. Получение ссылки подтверждено; наличие локального файла и чтение его содержимого ещё не проверены.
- Подробное условие домашнего задания может находиться во внешнем Google Drive. Текст в LMS тогда описывает формат сдачи, а не всю задачу. Внешнее условие в этом проходе не открывалось.

Экспорт MCP должен сохранять порядок блоков и ссылки на вложения, различать встроенное условие и внешний источник. PDF, ноутбуки, видео и HTML потребуют разных способов обработки. Полная выгрузка всех курсов ещё не выполнялась.

## Ведомость и средний балл

Существуют три разных представления, которые нельзя смешивать:

1. Прогресс курса: точный накопленный балл и оставшийся потенциал.
2. Ведомость: нормированные оценки работ, средние активностей, вклад по весам, округлённый итог и блокеры.
3. Электронная зачётка: результаты сессий, виды контроля и оценки, в том числе «Зачёт».

Наблюдение по БД:

| Активность | Выполнено по UI | Средний | Вес | Вклад | Порог среднего |
|---|---:|---:|---:|---:|---:|
| Домашние задания | 7 из 12 | 5.25 | 20% | 1.05 | Нет |
| Активность без веса | 0 из 1 | 0 | 0% | 0 | Нет |
| Контрольная работа | 1 из 2 | 3.3 | 30% | 0.99 | 3.5 |
| Проект | 0 из 1 | 0 | 20% | 0 | Нет |
| Зачёт | 0 из 1 | 0 | 30% | 0 | 3.5 |

Семь оценённых ДЗ: `10, 8, 10, 8, 10, 7, 10`, сумма 63. `63 / 12 = 5.25`, а среднее только оценённых работ — 9. Это конкретное подтверждение: отображаемое LMS среднее учитывает запланированное количество работ, а не только уже оценённые. Контрольная: `6.6 / 2 = 3.3`.

Прогресс возвращает `earnedScore=2.04`, `leftToEarnScore=7.333333333333333`, `maxScore=10`. Ведомость возвращает итог `2`; UI дополнительно показывает «Из-за блокера: 0» и требование сдать контрольную. Алгоритм округления и применения блокеров на всех граничных значениях не проверен.

В ответах есть `normalizationScore`, `normalizedScore`, `normalizedExtraScore`, `extraScore`, `bestScoresCount`, `averageScoreThreshold`, `isBlocker`, `blockerTriggered`. Для БД `bestScoresCount=null`; режим выбора лучших работ на других курсах не проверен. Отсутствующая оценка приходит `null`; экран открытого задания при этом способен показывать `0 / 10`. MCP должен сохранять `null`, а не превращать работу на проверке в нулевую оценку.

Важно различать:

- `exercisesCount` — число упражнений в определении активности;
- `maxExercisesCount` — число, используемое для планового объёма;
- персональные задания — то, что назначено конкретному студенту;
- выполненные работы — отдельный показатель UI.

Эти количества в исследованном курсе не совпадают. Нельзя вычислять «выполнено» простым подсчётом всех упражнений курса.

## Задания, статусы и сроки

Список активных заданий запрашивает состояния `inProgress`, `backlog`, `submitted`, `review`, `reworking`. В ведомости дополнительно наблюдались `evaluated`, `failed`.

| Значение API | Подтверждённая подпись UI |
|---|---|
| `backlog` | Задано |
| `submitted` | Решение прикреплено |
| `review` | На проверке |
| `evaluated` | Оценено |
| `failed` | Не сдано |
| `inProgress` | В работе — соответствует наблюдавшимся данным списка; отдельная детальная карточка этого состояния не проверена |
| `reworking` | Входит в запрос; отдельный пример и подпись не проверены |

В карточке работы доступны дата создания, начала, отправки, возврата, оценивания, исходный и индивидуальный дедлайны, балл, допбалл, активность, курс, тема, лонгрид и проверяющий. В открытом ДЗ видны прикреплённое решение и вкладки «Решение», «Комментарии», «Информация». Вкладка комментариев проверена: для ДЗ 8 БД «Нет сообщений», редактор, вложения и отправка. Сообщения не отправлялись. В истории решения читаются события смены статуса, сдачи, назначения проверяющего и LD.

В общем списке наблюдалось 37 активных работ: 18 в группе «Эта неделя», 19 в группе «Далее». В первой группе есть очень старые работы, а ответ включает `course.isArchived=true` для курса 2025 года. Следовательно:

- «Активные задания» не означает «только актуальные курсы».
- Подпись «Эта неделя» нельзя использовать как точный фильтр календарного интервала.
- MCP должен фильтровать по полным ISO-датам и отдельно по архивности курса.
- Состояние «Решение прикреплено» нужно передавать буквально; завершённость сдачи по одному названию нельзя додумывать.

## Late days

Общий баланс на момент исследования — 24 LD. Он отображается в шапке и встречается в данных студента как `lateDaysBalance`.

Детальный ответ задания содержит:

- `exercise.deadline` — исходный срок;
- `task.deadline` — индивидуальный срок;
- `lateDays` — использованные для работы дни;
- `isLateDaysEnabled` — признак на уровне персональной работы;
- `exercise.activity.isLateDaysEnabled` — признак активности.

Пример ДЗ 8 БД, taskId 2289310:

| Поле | Значение |
|---|---|
| Состояние | `review` / На проверке |
| Исходный срок | 2026-11-08T19:00:00+00:00 = 8 ноября 22:00 МСК |
| Индивидуальный срок | 2026-11-10T19:00:00+00:00 = 10 ноября 22:00 МСК |
| Использовано | 2 LD |
| LD разрешены в данных | Да |

Для ещё заданного ДЗ 10 БД открыт диалог «Перенести дедлайн», поле «Кол-во дней из 24», кнопки «Отменить» и «Перенести». Перенос не применялся. Запрос изменения, его валидация, максимумы по состояниям, правила возврата LD и возможность переноса после дедлайна не проверены.

`isLateDaysEnabled=true` не следует превращать в безусловное «прямо сейчас можно перенести на N дней»: кроме признака могут действовать состояние, дата и серверные ограничения. MCP полезно отдавать отдельно разрешение по данным, баланс, уже потраченные дни и подтверждённость доступного действия.

## Дополнительные функции и ограничения

- **Видео.** Список БД содержит 19 событий и фильтры; открытый семинар 14 ноября показал «Видеозаписей нет». Наличие строки события не доказывает наличие записи. Другие записи не проверены.
- **Расписание.** Есть повторяющиеся пары, даты действия, преподаватели, аудитории и незаполненные выборы времени. Сам выбор/перезапись не выполнялись.
- **Посещаемость.** Большинство курсов помечены «Недоступна», у одного доступна числовая статистика. «Недоступна» нельзя трактовать как 0%. Портал предупреждает, что появление посещения может занять неделю; подробности курса 1253 открыты, есть выбор даты; за 15.11.2026 — «Нет событий».
- **Зачётка.** Доступны зимние и летние сессии нескольких учебных лет; раскрыта одна прошедшая сессия, видны числовые оценки и зачёты. Соответствие предметов зачётки и отдельных LMS-курсов ещё не исследовано.

## Дополнительные подтверждения продолжения

### Второй и третий курс

Формула UI: ДЗ — 6 из 13, среднее 3,71, вес 20%, вклад 0,74; аудиторная активность — 1 из 28, среднее 0,32, вес 25%, вклад 0,08; КР — 15%; зачёт — 40%; итог 1. Оценённые ДЗ: 9,8; 9,5; 0; 10; 9; 10. Сумма 48,3 / 13 = 3,715..., в UI 3,71. Точный общий алгоритм округления/усечения не установлен.

Архивная ИБ 880: зачёт 9,12 × 25% = 2,28; лабораторные 15 из 15, среднее 9,86 × 50% = 4,93; коллоквиум 10 × 25% = 2,5; итог UI 10. Зачёт и коллоквиум помечены как блокеры; есть активность с весом 0%. Это проверка UI, не независимое воспроизведение серверной формулы по сырым данным третьего курса.

### Архив заданий

Архив запрашивает `state=evaluated&state=failed`; проверенный ответ — массив 698 работ. Есть сортировка `sortProperty=deadline&sortDirection=-1`. В архиве находятся и работы актуальных курсов. Завершённость работы, архивность курса и попадание срока в прошлое — три разных признака.

### История и LD

## Оставшиеся технические проверки перед реализацией

1. Автономный HTTP-клиент: авторизация, срок/обновление сессии, повторный вход, ошибки 401/403, CSRF для будущих операций изменения. Cookies и токены не экспортировались.
2. Локальная выгрузка PDF/ноутбука, извлечение текста, изображения и формулы, внешние условия в Drive.
3. Лучшие N работ, нормирование, допбаллы и другие стратегии попыток: наличие данных подтверждено, полный расчёт и все варианты поведения ещё не проверены. Для квиза проверено чтение завершённой попытки; новые не запускались.
4. Полные ограничения LD по датам/состояниям, лимиты и возврат. Изменять сроки ради исследования нельзя.
5. Надёжное получение полного текста Note вне браузера, актуальная общая статья о LD, вложения/экспорт Note.
6. Точные схемы API дополнительных разделов и история посещаемости за непустую дату; расписание и записи с существующим видео.
7. Time — отдельный внешний сервис; переписка и API не исследовались. Управление IT-аккаунтами, обращения, регистрация на мероприятия и запись на слоты не выполнялись.
