# Реализация локального MCP

> Исторический отчёт о runtime 0.1.0. Текущая поставка 0.3.0 описана в [distribution.md](distribution.md); локальный compact MCP работает в чатах.

Дата: 15 ноября 2026 года.

## Что готово

Python-пакет `cu-lms-mcp`, локальный transport stdio, 17 инструментов. Исполняемые точки входа: `cu-lms-mcp` и `python -m lms_mcp`. HTTP-порт MCP не открывает.

- `browser.py`: обнаружение Chrome/Chromium/Edge/Brave/Firefox/Yandex в PATH и стандартных каталогах Linux/macOS/Windows, выбор браузера и отдельный временный профиль WebDriver. Локальный канал драйвера использует 127.0.0.1 и исключение из прокси. Обычный профиль пользователя не читается.
- `auth.py`: асинхронный процесс входа с ручной авторизацией, фоновым ожиданием, API-проверкой, отменой и закрытием окна; пароль не читается. Cookies сохраняются после успешной проверки `/api/micro-lms/students/me`.
- `session.py`: Cookie header, JSON/storage state и Netscape, доменная изоляция LMS/Note, атомарная запись, POSIX-права, межпроцессная блокировка, защита нового входа от ротации старого запроса.
- `client.py`: только GET к фиксированным origin; запрет автоматических редиректов, обработка истёкшей сессии/HTML вместо JSON, ограничение ответа и сохранение ротации cookies.
- `service.py`: каталог с пагинацией, дерево курса, серверная ведомость/блокеры/прогресс, состояния и личные сроки заданий, LD, лонгриды, завершённые квизы.
- `content.py`: получение подписанной ссылки, загрузка только с исследованного S3-хоста без cookie/Authorization, локальное сохранение и извлечение PDF/ipynb/текста. Note читается headless-браузером с отдельной cookie при необходимости.
- `server.py`: инструменты MCP с аннотациями, типизированными параметрами и очищенными сообщениями ошибок.
- `cli.py`: запуск сервера, браузерный вход, скрытый ввод/импорт cookie, статус, удаление локальной сессии и генерация конфигурации.

Изменяющих учебные данные инструментов нет. Вход/импорт меняют только локальную сессию, экспорт — локальные файлы. `get_quiz_result` отказывается открывать новый или незавершённый тест.

## Проверка

Проверка полного набора 15.11.2026:

```text
LMS_MCP_BROWSER_TEST=1 .venv/bin/pytest -q
42 passed in 5.33s

.venv/bin/ruff check src tests
All checks passed!

.venv/bin/ruff format --check src tests
18 files already formatted
```

Браузерный тест использовал настоящий Chromium 153 и ChromeDriver 153, локальный HTTP-сайт с формой входа и HttpOnly-cookie. Он подтвердил всю цепочку: запуск → форма → cookie → проверка через HTTP API фикстуры → локальное сохранение → закрытие окна. Университет и реальные учётные данные в этом тесте не использовались. В процессе проверки устранены проксирование localhost и задержка при IPv6-разрешении адреса драйвера.

Тест stdio запускает отдельный процесс MCP, выполняет initialize, tools/list и tools/call, проверяет машинный ответ и ошибку при отсутствии сессии.

Контрактные тесты проверяют пагинацию 27 курсов, разные статусы/архивность, интервал дедлайнов в МСК, null-оценки, сохранение серверных блокеров, LD, ротацию и отмену входа, форматы cookies, ошибки доступа, отсутствие передачи LMS-cookie в Note/S3, скачивание/извлечение и чтение таблицы силлабуса.

## Что пока не подтверждено живым аккаунтом

- Новый HTTP-клиент не проходил реальный вход пользователя. В текущем окружении нет DISPLAY/WAYLAND_DISPLAY для интерактивного окна. Браузерный вход нужен на компьютере с графической сессией; альтернатива — локальный импорт cookie.
- Учебные GET-контракты опираются на исследованный API и тестовые ответы. Их полный регрессионный прогон по реальным курсам через этот клиент ещё не выполнен.
- Чтение Note через Selenium проверено фикстурой DOM; две реальные статьи ранее читались другим браузерным инструментом. Изменение вёрстки Note или требование отдельного входа может потребовать адаптации.
- Реальная выгрузка защищённого PDF этим клиентом ещё не проверена. Поддерживается только исследованный S3-хост. Drive и другие внешние хранилища возвращаются ссылками, OCR отсутствует.
- Физические запуски Firefox/Edge/Brave, а также Windows/macOS не проверялись. Обнаружение и адаптеры реализованы; требуются соответствующие браузеры и драйверы.
- Не подключены отдельный API чата комментариев, уведомления, расписание, посещаемость и видеозаписи. Полная серверная допустимость переноса LD не известна; инструмент возвращает её как неизвестную.

Список ограничений не выдаётся за успешную live-проверку. Для подключения и первого входа см. README и `examples/mcp.json`.

## Исправление выбора драйвера 15.11.2026

В реальном окружении одновременно установлены Chrome 152.0.7977.64, Chromium 153.0.8010.52 и системный chromedriver 153.0.8010.52. Раньше `auto` выбирал Chrome первым, а неявный Selenium Manager подхватывал несовместимый драйвер из PATH.

Теперь `auto` предпочитает совместимую локальную пару. Для явного выбора браузера проверяются версии; при несовместимости вызывается Selenium Manager с `--skip-driver-in-path`, `--avoid-stats`, фиксированным путём/версией браузера и запретом скачивания другого браузера. Системные бинарники не изменяются. Ошибка загрузки возвращается с рекомендацией выбрать Chromium или импорт cookie, без сырых подробностей исключения.

Регрессионный прогон после исправления: **48 passed in 6.60s**, включая реальный автоподбор Chromium и захват cookie на локальной форме. Добавлены случаи несовместимых версий, явного выбора Chrome, недоступной загрузки и неизвестной версии браузера.

Дополнительно проверен настоящий headless-запуск с явным выбором Chrome: браузер 152.0.7977.64 успешно запущен с отдельно подобранным chromedriver 152.0.7977.82. Кэш этой проверки — временная папка /tmp; системный chromedriver 153 оставлен без изменений. Портал в этой проверке не открывался.
