# CU LMS для ChatGPT

Курсы, ведомость, домашние задания, дедлайны, Late Days и материалы Центрального университета в обычном ChatGPT. Исходники и навык распространяются через [Zeevss/cu-vibe-mcp](https://github.com/Zeevss/cu-vibe-mcp).

MCP работает на твоём компьютере. Cookies остаются локально; ChatGPT получает результаты запрошенных операций. Для связи с облачным чатом используется **Secure MCP Tunnel**. GitHub хранит код и релизы, отдельный сервер проекта не нужен.

> Вход в LMS теперь выполняется через HTTP SSO в терминале, без поиска браузера и WebDriver. Живая начальная страница проверена; полный вход с паролем и MFA пока проверен на фикстурах, а не в реальном аккаунте. Силлабусы Note пока читаются через headless-браузер.

## Что умеет

- Актуальные и архивные курсы, темы и прогресс.
- Ведомость: официальные средние и итоговые баллы, активности, веса, блокеры; электронная зачётка.
- Домашние задания: условия, статусы, оценки, исходные и личные дедлайны, история событий.
- LD: баланс, потраченные дни и доступные серверные флаги переноса. Возможность нового переноса не вычисляется по догадке.
- Лонгриды, вложения и извлечение текста из PDF/ноутбуков; результаты завершённых тестов.
- Текст и таблицы силлабуса Note, если есть доступ. Для закрытых страниц может понадобиться отдельная cookie Note.

Инструментов сдачи работ, запуска тестов и расходования LD нет.

## 1. Установка

Целевые системы: **Windows, macOS и Linux**, Python 3.11+. Установи [uv](https://docs.astral.sh/uv/getting-started/installation/) и Git. Команды ниже одинаковы в PowerShell и терминале macOS/Linux:

```text
git clone https://github.com/Zeevss/cu-vibe-mcp.git
cd cu-vibe-mcp
uv sync --project packages/runtime --frozen --no-dev
```

Вместо Git можно скачать ZIP из [GitHub Releases](https://github.com/Zeevss/cu-vibe-mcp/releases), когда релиз опубликован, распаковать в постоянную папку и выполнить последнюю команду из неё. Нужен весь пакет, а не один `SKILL.md`. Папку не перемещай после настройки туннеля: в его конфигурации будут абсолютные пути.

Вход и чтение LMS не требуют браузера, графической сессии или доступа к профилю браузера. Для `get_syllabus` пока нужен совместимый браузер/WebDriver. Реальный запуск здесь проверяется на Linux; для Windows/macOS добавлена матрица CI, успешные запуски нужно смотреть в Actions.

## 2. Вход в ЦУ

Из папки проекта в **своём локальном терминале**:

```text
uv run --project packages/runtime --frozen cu-lms-mcp login
uv run --project packages/runtime --frozen cu-lms-mcp status --validate
```

Программа спрашивает email, пароль и код только на тех шагах, которые вернул SSO. Ввод скрыт; пароль и код не пишутся в файлы. На шаге кода `/resend` запрашивает новый код, `Ctrl+C` отменяет вход. На одном шаге допускается до пяти попыток ввода, повторная отправка — до двух раз. Автоматических повторов отправки пароля или кода нет.

Неверные данные позволяют повторить ввод по новой форме SSO. CAPTCHA, смена/восстановление пароля, настройка MFA и неизвестные формы останавливают вход с указанием следующего действия на сайте ЦУ. Обхода этих проверок нет. `--timeout 300` задаёт срок потока, допустимо 30–900 секунд; после долгого ожидания ввода просроченная форма не отправляется.

Сессия сохраняется только после успешного ответа API LMS. Неудачный вход не перезаписывает прежнюю сессию. Для уже готовой cookie остаётся скрытый локальный импорт:

```text
uv run --project packages/runtime --frozen cu-lms-mcp import-cookie
```

**Не вводи пароль, код или cookies в ChatGPT.** Инструмент `auth_login` даёт эту локальную команду; после твоего сообщения о завершении чат проверяет `auth_status(validate=true)`. Сам чат не запускает терминал и не видит промежуточные шаги входа.

## 3. Подключение к ChatGPT

Схема: `ChatGPT → Secure MCP Tunnel → локальный MCP → LMS ЦУ`.

Нужны доступ к custom MCP в ChatGPT, туннель Platform, привязанный к нужному workspace, и runtime API key для официального `tunnel-client`. Это отдельная настройка аккаунта; URL GitHub сам по себе MCP к чату не подключает. Компьютер и tunnel-client должны оставаться включёнными.

1. Установи официальный `tunnel-client` и создай туннель по [руководству OpenAI](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels).
2. Из папки проекта получи команду локального сервера:

   ```text
   uv run --project packages/runtime --frozen python tools/client_config.py --client chatgpt
   ```

3. Настрой профиль туннеля с этой командой, запусти `doctor`, затем `run`.
4. В ChatGPT открой Plugins → Add custom MCP server → Connection: Tunnel и выбери туннель.
5. Попроси: «Покажи мои задания на ближайшую неделю, баланс LD и ведомость». Успешный `get_dashboard` подтверждает подключение.

[Подробные команды для PowerShell и macOS/Linux](docs/chat-clients.md). Подключение реального аккаунта ChatGPT ещё не проверено. Навык в `skills/cu-lms/` содержит инструкции; основные правила также передаются через MCP, поэтому импорт отдельного навыка для этого пути не требуется.

## Вызовы и обновления

`serve --compact` публикует семь инструментов:

| Инструмент | Назначение |
|---|---|
| `get_dashboard` | Курсы, задания, LD и сводная ведомость одним вызовом |
| `describe_methods` | Индекс методов или до восьми подробных схем |
| `batch` | До 20 чтений с объединением одинаковых API-запросов |
| `auth_login` | Инструкция для локального SSO-входа |
| `auth_status` | Состояние сохранённой сессии, при необходимости проверка API |
| `auth_cancel` | Подсказка отмены через Ctrl+C в терминале входа |
| `check_updates` | Последний стабильный релиз и HEAD репозитория |

Проверка GitHub выполняется при запуске `serve`/`run`, кешируется на 24 часа и ничего не устанавливает. Ошибка сети не мешает работе. `LMS_MCP_CHECK_UPDATES=0` отключает её. Немедленная проверка:

```text
uv run --project packages/runtime --frozen cu-lms-mcp updates --force
```

Стабильный релиз сравнивается по номеру версии, commit — отдельно. Если revision неизвестен, `repository_changed=null`. Для обновления чистого Git-клона: останови туннель, выполни `git pull --ff-only`, повтори `uv sync --project packages/runtime --frozen --no-dev` и перезапусти туннель. При локальных изменениях сначала сохрани их и разберись с diff. Cookies находятся вне репозитория и переживают обновление.

## Данные и ограничения

Cookies хранятся в пользовательской папке `platformdirs`; путь можно задать через `LMS_MCP_DATA_DIR`. CLI входа и MCP должны использовать одну папку и одного пользователя ОС. На POSIX используются права 0700/0600; на Windows — права профиля пользователя. Шифрование хранилища пока не реализовано.

Успешный SSO-вход в LMS не означает вход в Note. Скачанные файлы остаются на локальном компьютере; облачный ChatGPT получает извлечённый текст, а не доступ к файловой системе. Частный API и тема SSO могут меняться.

## Разработка и выпуск

```text
packages/runtime/       HTTP SSO, работа с LMS, CLI и MCP
skills/cu-lms/          Инструкции работы с учебными данными
tools/                  Конфигурация, сборка и smoke-тест пакета
docs/                   Подключение, ограничения и исследование SSO
.github/workflows/      Проверки на трёх ОС и публикация релизов
```

```text
uv sync --frozen
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv run python tools/smoke_release.py
uv run python tools/build_release.py
```

Workflow публикует ZIP, `SHA256SUMS` и `release.json` при push тега `vX.Y.Z` после тестов и проверки версий. Перед тегом синхронизируй версии root/runtime, `__init__.py`, manifest и lock-файлов. Адрес `Zeevss/cu-vibe-mcp` уже записан в runtime; `tools/configure_repository.py` нужен при переносе репозитория. В архив не входят cookies и локальные загрузки.
